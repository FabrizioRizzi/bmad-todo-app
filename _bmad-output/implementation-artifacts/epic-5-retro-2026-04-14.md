## What went well

- **100% story completion** on the final epic — the entire PRD is now delivered across 5 epics and 18 stories.
- **Story 5.2 was the cleanest story in the project** — zero debug issues, zero patches needed on first implementation. Docker Compose with 3 services, secret-based credentials, migration entrypoint, and named volume all worked on first pass.
- **Page object centralization (Story 5.3):** `TodoPage` in `e2e/fixtures/todo-page.ts` owns all ARIA label construction, directly addressing Epic 4's locator fragility action item. No inline RegExp from user text in test specs.
- **Docker secrets pattern:** Credentials read from `/run/secrets/` at runtime, URL-encoded in entrypoint — production-grade credential management, not hardcoded env vars.
- **Multi-stage Docker builds:** Frontend image is 92.5MB (nginx:alpine), no Node runtime or source code in production. Backend is 320MB with production deps only.
- **11 new journey e2e tests** complement existing per-story specs — CRUD lifecycle, filtering, due dates, and error states covered at journey level.
- **Opus 4.6 across all 3 stories** — following Epic 4's action item, validated with measurably cleaner implementations.
- **Zero regressions** throughout the epic — 220 unit/integration tests and linter passed clean on every story.

---

## What was challenging

- **pnpm monorepo Docker context (Story 5.1):** 3 debug cycles, all workspace-related — `tsconfig.base.json` not copied into build context, test files pulled into production `tsc` build, root `prepare` script trying to run `simple-git-hooks` during `--prod` install. Classic monorepo-in-Docker gotchas.
- **Pre-existing flaky e2e tests surfaced (Story 5.3):** Story 3.2's "announces task count" and Story 3.3's "status sort" tests fail intermittently in full parallel suite due to shared database contamination. Pass reliably in isolation. Invisible before journey-level parallel execution.
- **Backend image size:** 320MB is heavier than ideal — mostly production `node_modules` (Fastify, Drizzle, plugins). Acceptable but not lean.
- **`drizzle.config.ts` in production image:** Documented exception to "no TypeScript source" AC. Needed for runtime migrations via `drizzle-kit migrate` in entrypoint.
- **Infrastructure stories lack automated tests:** Stories 5.1 and 5.2 verified by manual smoke tests only (Docker build, compose up, CRUD check, restart persistence). Appropriate but leaves a gap in automated verification.

---

## Learnings (carry forward)

1. **Thorough story preparation + Opus 4.6 = fast, clean delivery.** Story 5.2 proves that detailed dev notes, architecture references, and a capable model eliminate debug cycles entirely.
2. **Journey-level e2e tests expose problems granular specs miss.** Pre-existing flaky tests from Epic 3 were invisible until Story 5.3's parallel execution surfaced shared DB contamination.
3. **pnpm monorepo Docker builds need documented patterns.** Workspace-aware Dockerfile patterns (base tsconfig copying, test file exclusion, `--ignore-scripts` for production installs) should be institutional knowledge.
4. **Page objects solve locator churn.** Centralized label construction in a single class prevents cascading updates across specs when ARIA labels change.
5. **Model selection is validated across 2 epics.** Opus 4.6 correlated with zero structural deferrals in both Epic 4 (4 stories) and Epic 5 (3 stories).
